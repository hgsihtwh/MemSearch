# Пакетная транскрипция (MEM-30)

`transcribe.py` обрабатывает WAV из результата `research/download/download.py` и сохраняет `transcripts/{clip_id}.json` по [схеме транскрипта](../docs/data-format/schemas/transcript.schema.json). Исходные WAV и метаданные не удаляются и не изменяются.

## Запуск

Нужно заранее установить `faster-whisper` (с NumPy) в отдельное Python-окружение и подготовить веса модели, а также установить ffmpeg и добавить его в PATH либо указать `--ffmpeg ПУТЬ`. Аудио декодируется внешним ffmpeg в массив float32 16 кГц mono и передаётся модели в памяти; путь файла не передаётся PyAV, чтобы обойти обнаруженную несовместимость faster-whisper 1.2.1/PyAV 19. При первом использовании имени модели faster-whisper может скачать веса из сети; при отсутствии сети заранее поместите их в его кеш. Для GPU нужны совместимые CUDA/CTranslate2 библиотеки. Этот модуль не устанавливает зависимости. Формат ввода: PCM WAV `audio/{clip_id}.wav`, где `clip_id` — положительное целое без ведущих нулей. Директории результатов лучше размещать вне репозитория.

Из корня репозитория, указав Python окружения с faster-whisper:

```bash
python ml/transcribe.py --input D:/memsearch_dl --out D:/memsearch_dl/transcripts --include-clips
```

По умолчанию используется `large-v3`, устройство `auto` и автоопределение языка `--language auto`. Для принудительного русского укажите `--language ru`. CPU-вариант:

```bash
python ml/transcribe.py --input D:/memsearch_dl --out D:/memsearch_dl/transcripts --include-clips --model small --device cpu --compute-type int8
```

`--include-clips` добавляет к списку аудиофайлов ID по именам `clips/{clip_id}.json`, чтобы обнаружить отсутствие WAV. Содержимое метаданных не читается. Без флага обнаружить отсутствующий файл невозможно. Каталог `clips/` при включённом флаге обязателен. Пустой набор входных файлов считается ошибкой. Аудио с некорректным именем включается в отчёт как ошибка.

Внутри входного каталога `--out` разрешён только в `transcripts/`; нельзя писать в `audio/` или `clips/`, в том числе через символьные ссылки. Вне входного каталога можно выбрать отдельную папку. Существующие результаты перед пропуском проверяются: корректный JSON без лишних и дублирующихся полей, совпадающий ID, типы, непустые строки и неотрицательные конечные числа. Повреждённый результат даёт `error` и не меняется; для явной замены добавьте `--overwrite`. Символическая ссылка вместо транскрипта не принимается. Запись производится через временный файл и атомарную операцию; без `--overwrite` требуется поддержка hard links файловой системой. Для параллельных запусков используйте разные выходные каталоги; защита путей не предназначена для враждебной одновременной подмены каталогов/ссылок.

Модель загружается один раз только при первом валидном WAV, для которого ещё нет результата. Сначала применяется VAD с порогом 0.3 и beam size 5. Если сегментов с текстом нет, проводится повтор без VAD. Пустой результат после повтора сохраняется с `segments: []` и статусом `no_speech`: **речь не обнаружена, требуется проверка**, а не гарантия отсутствия речи. Непустой результат тоже не доказывает наличие речи: возможны галлюцинации (MEM-76, клипы 31 и 66). Всем новым результатам ставится `review_required: true`. Ошибки модели, ffmpeg, чтения, инициализации и записи не считаются отсутствием речи. WAV проверяется на пустоту, повреждение заголовка и усечение PCM-данных, но произвольные дефекты записи проверить невозможно.

Семантические аномалии времени — конец после длительности, конец до начала, нарушение порядка начал сегментов — вычисляются **до округления** и выводятся в `anomalies` отчёта с нулевым индексом и исходными значениями. Сегменты не обрезаются и не сортируются; `start` и `end` в транскрипте округляются до двух знаков. Отрицательные или не конечные значения недопустимы. При повторе `skipped` содержит `result_status` (`ok` или `no_speech`), `no_speech`, `review_required`, `path` и аномалии, вычисленные по сохранённому JSON. Округление может скрыть исходную аномалию, поэтому восстановленные при повторе аномалии не обязательно совпадают с первоначальными: сохраняйте первоначальный отчёт. При создании `ok` означает лишь сохранённый непустой вывод модели, а не подтверждённую речь или правильные таймкоды.

В stdout после завершения выводится JSON-массив записей с `clip_id`, `status` и, при ошибке, `error`; для результатов указан `path`. Статусы: `ok`, `no_speech`, `skipped`, `missing_audio`, `error`. Код выхода 0 — без ошибок и отсутствующих WAV, 1 — хотя бы один `error` или `missing_audio`, 2 — ошибка настройки или отчёта.

Для долговечного отчёта укажите `--report D:/memsearch_asr_report.jsonl`: создаётся только новый файл вне входного и выходного каталогов (включая разрешённые ссылки `audio/`, `clips/`), без перезаписи даже с `--overwrite`. Родительский каталог должен существовать. Каждая завершённая запись немедленно записывается отдельной строкой JSON, сбрасывается и синхронизируется с файловой системой. При ошибке записи обработка останавливается. Уже завершённые строки доступны после прерывания; при аварии во время записи последняя строка может быть неполной, а между сохранением транскрипта и отчёта возможен разрыв. Повтор позволяет восстановить статус и видимые по округлённым данным аномалии, но не исходную точность. Гарантии фактической сохранности зависят от ОС и носителя. Отчёт содержит пути и данные для проверки: храните его безопасно. Без `--report` stdout теряется при прерывании; перенаправление оболочкой может перезаписать файл.

## Нарезка транскриптов (часть MEM-31)

`chunking.chunk_transcript(transcript, caption=None)` возвращает объект по схеме `docs/data-format/schemas/chunks.schema.json`: для речи применяются окна 15 секунд с шагом 7 секунд, в каждое окно попадают целые пересекающиеся сегменты. Поэтому реальные границы фрагмента могут быть длиннее окна. Соседние окна с одним и тем же набором сегментов объединяются. В отличие от эксперимента MEM-76 одинаковые подпись и речь сохраняются отдельно, а повтор фразы в другое время не теряется. Пустая подпись не добавляется; длинная подпись очищается по правилам эксперимента и ограничивается 1000 символами. Векторизация выполняется отдельно через `ml.embeddings.EmbeddingAdapter`: ему передаётся заранее загруженный E5 encoder; адаптер возвращает float32-векторы и метаданные. Запись в БД и пакетная индексация — в разделе ниже.

Некорректные, неупорядоченные и выходящие за длительность таймкоды отклоняются, а не исправляются автоматически. Проверяйте проблемные исходные транскрипты; не каждый корректный по времени транскрипт обязательно качественный. Готовые транскрипты коллекции, уже очищенные от галлюцинаций и таймкодов за концом аудио, — в [`research/transcription/`](../research/transcription/) (MEM-30).

## Индексация в pgvector (MEM-31)

`index_collection.py` атомарно заменяет фрагменты `caption` и `speech` выбранных роликов коллекции: режет транскрипт (`chunking`), строит векторы multilingual-e5-large (`embeddings`), пишет в таблицу `chunks` вектор, таймкоды, текст и `tsv`; ссылка на видео — через `chunks.clip_id → clips.url`. Фрагменты других источников (`ocr`, `scene`) и исходные файлы не меняются. Индекс HNSW (`vector_cosine_ops`) создаёт миграция.

`index_cli.py` — запуск из командной строки. Ролики уже должны быть в БД (импорт — MEM-34); соответствие номеров паспорта и `clips` проверяется по платформе и внешнему ID. Нужен `sentence-transformers` (с PyTorch) — в отдельном окружении, как faster-whisper.

```sh
export MEMSEARCH_DSN=postgresql://USER:PASSWORD@127.0.0.1:5432/memsearch
# 1. План: проверка транскриптов и соответствия роликов, хеш подтверждения
python -m ml.index_cli plan --collection UUID --passport research/collection/passport.csv \
    --transcripts research/transcription/transcripts
# 2. Индексация с хешем из плана
python -m ml.index_cli index --collection UUID --passport research/collection/passport.csv \
    --transcripts research/transcription/transcripts --confirm-mapping ХЕШ
# 3. Проверочный поиск с замером времени
python -m ml.index_cli search --collection UUID --query "кот играет на пианино"
```

Проверка 26.11.2026 на PostgreSQL 16 + pgvector 0.8.0 из `compose.yaml`, векторы на GPU (RTX 4060): проиндексированы все 88 роликов с транскриптами — **751 фрагмент** (665 речи с таймкодами, 86 подписей) за 1,5 мин вместе с загрузкой модели. По 110 контрольным запросам MEM-17 ([`research/embeddings_check/results/mem31_pgvector_check.json`](../research/embeddings_check/results/mem31_pgvector_check.json)):

| Метрика | Индекс в pgvector | Эксперимент MEM-76 (в памяти) |
|---|---|---|
| Recall@10 | 0,963 | 0,963 |
| MRR | 0,910 | 0,912 |
| Recall@1 | 0,869 | 0,869 |
| Поиск (векторизация запроса + БД), медиана / p95 | 48 / 75 мс | — |
| из них запрос к БД, медиана / p95 | 7,7 / 11,8 мс | — |

Ролики №30, 55, 56 не скачались (MEM-20): транскрипта нет, а подпись в БД пуста, хотя в паспорте она записана вручную. `index_collection` умеет индексировать ролик только по подписи (транскрипт `None`), а `index_cli` берёт лишь ролики с транскриптами — после импорта MEM-34 с подписями из паспорта эти три ролика нужно проиндексировать по подписи (в MEM-76 они искались так же).

Совпадение метрик с MEM-76 подтверждает, что разбиение и векторы в БД те же, что в эксперименте. Время без загрузки модели (~20 с один раз при старте процесса) — **критерий «быстрее 1 с» выполнен с запасом**. На 751 строке планировщик выбирает полный перебор вместо HNSW — это быстрее для такой маленькой таблицы; поведение HNSW на 100 тысячах векторов проверено в MEM-78 (`research/pgvector_bench`).

## Оценка качества поиска (MEM-39)

`evaluate.py` прогоняет контрольные запросы MEM-17 через поиск в pgvector и сохраняет JSON-отчёт: Recall@1, Recall@10, MRR, время поиска, промахи и ранжирование каждого запроса.

```sh
MEMSEARCH_DSN=postgresql://... python -m ml.evaluate --collection UUID --out research/search_eval/report.json
```

Первый замер (26.11.2026, [`research/search_eval/report_mvp.json`](../research/search_eval/report_mvp.json)): **Recall@10 0,963, MRR 0,908, Recall@1 0,869**, поиск — медиана 53 мс. Не найдены в топ-10 4 запроса: «как делать присед», «техника приседа», «рецепт, спетый как песня», «полезные булочки с корицей без сахара» — цели для подбора параметров (MEM-41).

## Полнотекстовый поиск (MEM-80)

Два модуля, оба работают с PostgreSQL через asyncpg и не меняют исходные таблицы.

- `lexical.py` — **замер базовой линии** по контрольным запросам MEM-17 во временной таблице: `MEM80_TEST_DSN=postgresql://... python -m ml.lexical > результат.json`. Результаты и сравнение с MEM-76 — в [`research/embeddings_check/README.md`](../research/embeddings_check/README.md).
- `lexical_persistent.py` — **постоянный индекс для приложения**. Документ ролика: название, подпись, сегменты транскрипта (`transcript_segments`) и фрагменты текста в кадре или описания сцены (`chunks.source` = `ocr`/`scene`). Хранится в отдельной схеме `mem80_lexical` (таблица `clip_documents`, один GIN-индекс), удаление ролика или коллекции удаляет и документ.

```sh
export MEMSEARCH_DSN=postgresql://USER:PASSWORD@127.0.0.1:5432/memsearch
python -m ml.lexical_persistent install                                # один раз, идемпотентно
python -m ml.lexical_persistent index --collection UUID               # пересобрать коллекцию
python -m ml.lexical_persistent search --collection UUID --query "кот" --limit 10
```

Индекс — снимок данных, а не триггер: после изменения роликов или транскриптов коллекции снова выполните `index`. UUID коллекции не является ключом доступа: проверку прав выполняет вызывающий код.

Проверка 26.11.2026 на PostgreSQL 16 из `compose.yaml`: проиндексированы все 91 ролик демонстрационной коллекции (транскрипты MEM-30, подписи из результатов загрузки MEM-20). По 107 контрольным запросам с ответом Recall@10 (hit@10) = 0,869, macro Recall@10 = 0,828, MRR = 0,760; время `search` — медиана 1,3 мс, p95 1,9 мс. MRR выше, чем у замера `lexical.py` (0,720), за счёт очищенных транскриптов и полных подписей. Тест на настоящей БД (`MEM80_RUN_DOCKER_TESTS=1`) сам поднимает отдельный контейнер.

## Проверки без скачивания модели

Из корня репозитория:

```sh
# Установите зависимости разработчика из lock-файла проекта.
uv sync --locked
uv run --locked pytest
```

На этой Windows-машине в окружение Hermes может быть добавлен чужой `PYTHONPATH`. Если Python загружает несовместимые пакеты другого окружения, для разового запуска из Git Bash используйте `env -u PYTHONPATH .venv/Scripts/python.exe -m pytest`. Для ML-тестов отдельно:

```sh
env -u PYTHONPATH .venv/Scripts/python.exe -m pytest ml/tests -q
env -u PYTHONPATH .venv/Scripts/ruff.exe check ml
env -u PYTHONPATH .venv/Scripts/ruff.exe format --check ml
env -u PYTHONPATH .venv/Scripts/pyright.exe ml
```

Тесты подменяют модель и не устанавливают зависимости/веса. Они не проверяют качество реального ASR, GPU и совместимость установленной версии faster-whisper.
