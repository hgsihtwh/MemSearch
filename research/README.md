## Повторный замер pgvector + HNSW (MEM-78)

Прогон 26.11.2026: PostgreSQL 16.10, pgvector 0.8.0.

### Запуск

Заполните `.env`, установите зависимости (`uv sync --locked`) и выполните из корня репозитория:

```sh
docker compose up -d --wait postgres
uv run --locked python research/pgvector_bench/bench.py --data uniform --output results_uniform --recall-queries 50 --ef-search 40 100 200
uv run --locked python research/pgvector_bench/bench.py --data clustered --dims 1024 --sizes 100000 --output results_clustered --recall-queries 50 --ef-search 40 100 200
```

### Что проверяется

- `uniform`: случайные нормированные векторы размерностей 768 и 1024, объёмы 10, 50 и 100 тысяч.
- `clustered`: 100 тысяч векторов размерности 1024, сгруппированных по темам и роликам.
- HNSW: `m=16`, `ef_construction=64`, `ef_search=40/100/200`, косинусное расстояние.
- После 10 прогревочных запросов выполняются 100 измерений времени. Recall@10 — доля
  найденных точных ближайших векторов, проверенная на 50 запросах полным перебором.

Использование HNSW принудительно задано настройками планировщика и проверяется через
`EXPLAIN (ANALYZE, BUFFERS)`. Для каждого объёма сохраняются результаты и планы запросов.
Скрипт работает во временных таблицах, не затрагивая данные приложения.

### Результаты

| Сценарий | Таблица | CSV | Планы запросов |
|---|---|---|---|
| Случайные векторы | [Markdown](pgvector_bench/results_uniform.md) | [CSV](pgvector_bench/results_uniform.csv) | [JSON](pgvector_bench/results_uniform_plans.json) |
| Сгруппированные векторы | [Markdown](pgvector_bench/results_clustered.md) | [CSV](pgvector_bench/results_clustered.csv) | [JSON](pgvector_bench/results_clustered_plans.json) |

**Поиск топ-10 в БД быстрее 2 с подтверждён** для обеих размерностей на объёмах до 100 тысяч
векторов: максимальное измеренное время на случайных данных — 27,50 мс.
На верхнем объёме при `ef_search=200`:

| Данные | Размерность | Индекс, МиБ | p95, мс | Recall@10 |
|---|---|---|---|---|
| Случайные | 768 | 390,6 | 19,07 | 0,164 |
| Случайные | 1024 | 781,3 | 22,43 | 0,146 |
| Сгруппированные | 1024 | 781,3 | 4,37 | 0,968 |

Качество зависит от распределения: на случайных данных HNSW пропускает много соседей.
`ef_search=200` подходит как кандидат для проверки на настоящих эмбеддингах.
В таблицах результатов столбцы «МБ» фактически рассчитаны в МиБ (байты / 2²⁰).

При среднем числе 9 фрагментов на ролик 100 тысяч векторов покрывают около 11 тысяч роликов.
Это замер БД одним клиентом на синтетических данных; время полного API, работа с фильтрами
и параллельная нагрузка требуют отдельной проверки.

Старые `pgvector_bench/results.csv` и `results.md` от 29.10.2026 оставлены для истории:
их соответствие текущему скрипту не установлено, для выводов используются новые результаты.
