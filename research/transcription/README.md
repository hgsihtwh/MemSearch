# Транскрипты коллекции (MEM-30)

Итоговые транскрипты всех доступных роликов коллекции с таймкодами — вход для индексации (MEM-31), полнотекстового поиска (MEM-80) и импорта в БД (MEM-34).

| Путь | Что там |
|---|---|
| [`transcripts/{clip_id}.json`](transcripts/) | Транскрипт по [схеме transcript](../../docs/data-format/schemas/transcript.schema.json) (MEM-79); `segments: []` — речь не обнаружена |
| [`report.csv`](report.csv) | Статус каждого из 91 ролика паспорта, флаг `no_speech`, что изменено при очистке |
| [`make_transcripts.py`](make_transcripts.py) | Скрипт, который собирает обе части: `python research/transcription/make_transcripts.py` |

## Откуда транскрипты

Распознавание выполнено в Colab на T4 при прогоне MEM-76 (29.10.2026, [`../embeddings_check/results/transcripts/`](../embeddings_check/results/transcripts/)): faster-whisper **large-v3**, float16, `beam_size=5`, `language='ru'`, VAD с порогом 0,3, при пустом результате — повтор без VAD. Это тот же алгоритм, что в модуле [`ml/transcribe.py`](../../ml/transcribe.py), поэтому повторно коллекцию не распознавали. Для нового прогона модуль вызывается одной командой (см. [`ml/README.md`](../../ml/README.md)):

```bash
python ml/transcribe.py --input D:/memsearch_dl --out D:/memsearch_dl/transcripts --include-clips --language ru --report D:/asr_report.jsonl
```

Скрипт `make_transcripts.py` ничего не распознаёт: он берёт транскрипты MEM-76 (их файлы не меняются) и исправляет две систематические ошибки Whisper.

1. **Галлюцинации на тишине и музыке.** На отрезках без речи large-v3 дописывает фразы из обучающих субтитров: «Субтитры сделал DimaTorzok», «Субтитры создавал DimaTorzok», «Субтитры подогнал «Симон»», «Продолжение следует...», «Музыка». Такие сегменты удаляются целиком (73 сегмента в 27 роликах). Без этого фраза про субтитры попадала бы в поиск: в транскриптах MEM-76 она есть у 21 ролика.
2. **Таймкоды за концом аудио.** Последнее 30-секундное окно Whisper дополняет тишиной, поэтому сегмент может заканчиваться (…9,98 с) или даже начинаться позже конца звука. Сегмент, начинающийся после конца аудио, удаляется (2 сегмента ролика №84 — повтор последней фразы), заканчивающийся позже — обрезается по длительности (7 сегментов). Без этого модуль разбиения `ml/chunking.py` отклоняет 14 из 88 транскриптов.

## Результат

| Статус | Роликов | Что значит |
|---|---|---|
| `ok` | 62 | Речь распознана, сегменты с таймкодами |
| `no_speech` | 26 | Речь не обнаружена: `segments: []`, `no_speech = да`; ролик ищется по подписи |
| `unavailable` | 3 | №30, 55, 56 не скачались (вход по cookies / закрыты для российского IP, см. [MEM-20](../download/README.md)) — транскрипта нет |

**Ролики без речи помечены** в `report.csv` флагом `no_speech`, а в самом транскрипте — пустым списком сегментов (правило MEM-79). Как и в `ml/transcribe.py`, «речь не обнаружена» — это результат модели, а не гарантия: см. ниже.

### Расхождения с паспортом коллекции (нужна проверка)

- **9 роликов с речью по паспорту получили `no_speech`:** №15, 24, 26, 32, 37, 59, 66, 67, 72. Их транскрипты MEM-76 целиком состояли из галлюцинаций (у №37 — 25 сегментов «Субтитры сделал DimaTorzok»): модель не выделила голос поверх музыки — та же проблема, что у №66 в MEM-16. Сейчас эти ролики ищутся только по подписи. **Их нужно перераспознать** с другими параметрами (без VAD, `condition_on_previous_text=False`, `hallucination_silence_threshold`) и сравнить с паспортом. Аудио всех девяти скачивается (прогон загрузки 26.11.2026).
- **15 роликов без речи по паспорту получили `ok`** (пометка в `note`): это распознанный текст песен и закадровый голос, а не галлюцинации — для поиска он полезен, поэтому сохранён.
