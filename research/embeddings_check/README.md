# Выбор модели эмбеддингов (MEM-76)

Ноутбук `embeddings_check.ipynb` (собирается `make_notebook.py`) запускается в Colab на T4 и воспроизводится с нуля: скачивает и распознаёт ролики коллекции (faster-whisper large-v3), режет транскрипты на фрагменты, строит векторы двумя моделями, ищет по косинусной близости в памяти и считает метрики по контрольным запросам MEM-17. Результаты прогона 29.10.2026 — в `results/` (`comparison.csv`, `per_query.csv`, транскрипты 88 роликов).

**Условия:** 91 ролик (у 88 есть транскрипт; №30, 55, 56 не скачались — ищутся только по подписи), 107 запросов с ответом + 3 без ответа. Ролик ищется по всей коллекции; оценка ролика — лучший из его фрагментов; подпись — отдельный фрагмент.

## Выводы

1. Обе модели с запасом проходят цель Recall@10 ≥ 0,8 и обгоняют поиск по словам (0,77) на ~0,2.
2. **multilingual-e5-large лучше ставит правильный ролик наверх**: MRR 0,91 против 0,87, Recall@1 0,87 против 0,82. По Recall@10 модели равны (разница в 1 запрос).
3. **Окно 15 с / шаг 7 с** — лучшее на запросах Анастасии; весь транскрипт одним куском заметно хуже (MRR 0,83). Кроме того, e5 читает не больше 512 токенов — длинные куски обрезаются.
4. **Реранкер не берём:** прибавка +0,01 MRR, а на CPU он тратит ~40 с на запрос при требовании ≤ 2 с. Вернуться к нему можно только при сервере с GPU.
5. **Ограничение e5:** сходство у него сжато (топ-1 с ответом 0,85, без ответа 0,82), порог «ничего не найдено» по нему не поставить; у bge-m3 разрыв больше (0,61 против 0,49). Как отличать запросы без ответа — в MEM-41 (гибрид с BM25 или порог).
6. Цифры оптимистичны: коллекция маленькая (91 ролик), запросы писали люди, знающие ролики. На большой коллекции метрики будут ниже — финальный замер в MEM-55.
