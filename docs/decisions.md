# Решения по продукту после исследования

> Зафиксировано 10.10.2026 по итогам конкурентного анализа ([competitors](competitors/README.md)), разбора API ([api](api/README.md)) и анкеты (35 ответов, [anketa-results](research/anketa-results.md)).

## 1. Платформа: mobile-first веб-приложение

**Решение.** Делаем веб-приложение, которое проектируется и вёрстается сначала под телефон. Его можно установить на главный экран как приложение (PWA).

**Почему.** 76 % опрошенных пользовались бы сервисом с телефона, 6 % — с компьютера. Ответ «работает только с компьютера» оттолкнёт 54 %.

**Что меняется.** Вайрфреймы, прототип, UI-кит и макеты (MEM-25, MEM-71, MEM-32, MEM-33, MEM-40) делаются сначала для мобильного экрана, десктоп — адаптация. Каркас клиента и страницы (MEM-36, MEM-43, MEM-44) — тоже mobile-first.

## 2. Первый вход: перенос всего «Избранного» через расширение браузера

**Решение.** Первичный перенос сохранённых роликов делаем **расширением браузера**, а не букмарклетом. Пользователь ставит расширение, открывает «Избранное» и нажимает одну кнопку. Расширение само прокручивает страницу, собирает ссылки и отправляет их в сервис.

**Почему.** Букмарклет слишком сложен для обычного пользователя: перетащить закладку, открыть «Избранное», нажать, вставить ссылки. Расширение делает всё одной кнопкой. Перенос всего «Избранного» в пару кликов люди оценили в 3,38 из 5, а ручное добавление каждого ролика отталкивает 37 %.

**Ограничения.**
- Расширение работает в браузере на компьютере. Первичный перенос — разовое действие, поэтому один раз сесть за компьютер допустимо.
- Расширение зависит от вёрстки страницы «Избранного», и при изменениях на платформе его придётся чинить.

**Что меняется.** MEM-74 «Расширение браузера» (оценка ~10 ч) переходит из бэклога в план и заменяет букмарклет MEM-83 (2 ч).

## 3. Дальнейшее добавление: из приложения на телефоне

**Решение.** Каждый следующий ролик пользователь добавляет с телефона в момент просмотра, через «Поделиться»:
- **Android** — установленное веб-приложение появляется в меню «Поделиться» любой видеоплатформы (Web Share Target): одно касание.
- **iPhone** — Safari не поддерживает приём «Поделиться» веб-приложениями, поэтому там работает **Telegram-бот** (MEM-85): «Поделиться» → Telegram → бот.
- **Везде, на любом устройстве** — остаётся запасной способ: **скопировать ссылку на ролик и вставить её в приложение** (одну или сразу несколько, по одной на строку). Он работает, если «Поделиться» недоступно, Telegram не открывается или платформа не поддерживается ботом. Реализован в странице добавления (MEM-44) и API (MEM-42).

**Почему.** Новые ролики сохраняют часто: 44 % — несколько раз в неделю. Это происходит на телефоне, и копировать ссылку вручную никто не будет. 21 % и так пересылают ролики себе в Telegram.

**Ограничение.** Telegram в России с 2026 года практически заблокирован. Пользователи заходят в него через VPN, а нашему серверу нужен отдельный сервер за границей или прокси для бота. Это принятое исключение из правила «всё без VPN».

**Что меняется.** Для приёма «Поделиться» в веб-приложении нужна отдельная задача: манифест PWA и обработка входящей ссылки, около 3–4 ч.

## 4. Фильтры урезаны

**Решение.** В версии 1.0 остаётся только ограничение поиска по теме (входит в раздел «Темы», MEM-52). Фильтры по дате, автору и длительности убраны в бэклог (MEM-51).

**Почему.** Это самая низкооценённая функция анкеты: 3,38 из 5, только 41 % поставили 4–5. Пользователи ищут строкой, а не фильтрами. Освободившиеся часы отданы Telegram-боту.

## 5. Поиск по изображению — обязательно, после MVP

**Решение.** Поиск по тому, что видно в кадре, становится обязательной функцией версии 1.0. Делается после демонстрации MVP 17.11.

**Почему.**
- 74 % помнят о потерянном ролике то, что было в кадре.
- Функция на третьем месте по полезности: 4,00 из 5.
- Из 10 описаний потерянных роликов 6–7 визуальные: мемы, животные, танцы, надписи на экране.
- Одной распознанной речи для таких роликов недостаточно.

**Как делаем (предложение).**
1. **Текст в кадре (OCR)** по ключевым кадрам — надписи мемов и подписи. Дешевле всего и закрывает самые частые случаи.
2. **Векторы кадров** мультиязычной моделью «картинка — текст» (семейство CLIP/SigLIP с поддержкой русского). Это поиск по описанию сцены: «собака бежит по полю», «девушка на мотоцикле». Векторы хранятся в том же pgvector.
3. Поиск по загруженному скриншоту — пожелание из анкеты, вторая очередь.

**Что меняется.** Функция 6.13 «Анализ видеоряда» в концепции повышается с низкого приоритета до среднего. Задача MEM-58 выходит из бэклога. Модель выбираем замером на нашей коллекции, так же как ASR и эмбеддинги.

## 6. Источники роликов: TikTok в первую очередь, затем VK

**Решение.** Сервис работает с TikTok и VK Клипами, **TikTok — в первую очередь**: коллекция для демо (~70 % TikTok), скрипт загрузки, расширение и «Поделиться» сначала делаются и проверяются для TikTok.

**Почему.** Главная платформа у 68 % опрошенных — TikTok, у VK Клипов — у 3 %. VK оставляем как второй источник: он работает из России без VPN.

**Риск.** TikTok для российских IP ограничен. Скачивание роликов с сервера в России проверяется первым делом в MEM-20; если не работает — загрузка идёт через прокси, как и для Telegram-бота. Обсудить с заказчиком.

## 8. Большие коллекции

**Проблема.** 66 % опрошенных «никогда не долистывали» до старых сохранённых роликов — там сотни и тысячи видео. Перенос и обработка 2000 роликов займут часы (≈ 11 ч на GPU, больше суток на CPU), массовое скачивание может привести к блокировке сервера платформой.

**Решение.**
- Расширение отправляет ссылки пачками по ходу прокрутки, показывает прогресс, умеет продолжить с места остановки; перед стартом пользователь выбирает объём: последние 200, за год или всё (MEM-74).
- Обработка в два прохода: быстрый (название, описание, хештеги, готовые субтитры платформы — ролик сразу ищется) и полный фоном (речь, текст в кадре, кадры); новые ролики через «Поделиться» и бота — вне очереди; скачивание с ограничением скорости и повторами (MEM-42).
- Прогресс «обработано N из M» на странице добавления, искать можно сразу (MEM-44).
- Краткие описания — фоном с низким приоритетом, ролики из выдачи — вне очереди, с кэшированием (MEM-47).
- Проверить, отдаёт ли yt-dlp готовые субтитры TikTok и VK (MEM-20).
- Требование к большим коллекциям — в SRS (MEM-22) и в концепции (8.6, «Масштабируемость»).

## 9. Языковая модель: Kimi вместо GigaChat

**Решение.** Краткие описания роликов (MEM-47) и названия тем (MEM-48) делает **Kimi (Moonshot AI)**. GigaChat отказались как от слабой модели.

**Как подключаем.** Прямой API Moonshot из России недоступен, российские карты не принимаются. Поэтому — через российский агрегатор с OpenAI-совместимым API и оплатой в рублях (например, AITUNNEL; Kimi K2 — порядка 80 ₽ за 1 млн входных и 380 ₽ за 1 млн выходных токенов по данным агрегатора). Работает с сервера в России без VPN.

**Стоимость.** Одно описание — ~1 200 токенов на вход и ~100 на выход, то есть ~0,1–0,2 ₽; коллекция из 2000 роликов — пара сотен рублей. Нужно пополнить баланс (от ~500 ₽).

**Риски.** Зависимость от посредника; вокруг Moonshot в 2026 году идут разговоры о санкциях США. Поэтому модель и адрес API задаются настройкой — Kimi меняется на DeepSeek или Qwen без изменения кода.

## 10. Без ручных папок — как в mymind

**Решение (10.10).** Ручных папок и подборок нет. Коллекция организуется автоматически: **автотеги** (редактируются) и **темы** (BERTopic, переименовываются, фильтр выдачи по теме), MEM-48, MEM-52. Пользователь ничего не раскладывает сам.

**Рассматривали.** «Подборки»: создаются вручную, ролик может лежать в нескольких, расширение переносит коллекции TikTok. Довод «за» — папками в TikTok пользуются 28 % опрошенных. Отказались: ручная организация — лишняя работа, а Ника в спринте 8 и так перегружена (~8–10 ч сверху). Если на юзабилити-тесте (MEM-56) будут просить папки, вернуться к идее после 1.0.

**Теги вручную — есть.** Пользователь добавляет свои теги и правит автоматические (ФТ-5.2 в SRS); при пересчёте тем свои теги не удаляются. Нет только ручных папок.

## 11. Выдача — ролики целиком, а не куски

**Решение (10.10).** Внутри поиск ведётся по фрагментам ролика (фразы речи и сцены с таймкодами) — так точнее. Но пользователю показываются **ролики целиком**: одна карточка на ролик (превью, название, автор, краткое описание) и одна строка «почему найден» — источник (речь / текст в кадре / кадр) и короткая цитата с подсветкой. «Открыть в TikTok / VK» открывает ролик целиком.

**Не делаем** (было в UX-разборе Twelve Labs): ленту кадров фрагмента, таймкоды «00:45–00:50» в выдаче, счётчик «N совпадений в M роликах», окно «Транскрипт фрагмента», блок «Совпадения в ролике». Вместо последнего — подсветка мест совпадения в транскрипте внутри карточки ролика.

**Где внесено:** SRS (ФТ-3.4, 3.5, 4.1, 4.2, 4.4, 4.5 исключено, ПР-2), Figma (IA, карточки экранов, функционал, user flow, карта экранов, выводы по Twelve Labs).

## 12. Коллекция — настоящее «Избранное», без подгонки

**Решение (14.10).** Демо-коллекция (MEM-23) — это реальные лайки и «Избранное» участников команды как есть: темы и доля речи не выравниваются искусственно. Так выглядит коллекция настоящего пользователя, и на ней честнее проверять поиск. Разнообразие даёт второй человек (Ника, другие интересы) и VK.

**Наблюдение по 75 роликам TikTok Анастасии:** речь есть у 41 (55 %), текст в кадре — у 71 (95 %), «только музыка» — у 33. Это подтверждает решение 5: без поиска по тексту в кадре и кадрам почти половину реальных роликов не найти по речи (ср. анкета: 74 % помнят, что было в кадре).

**Следствие для критериев MEM-23:** «≥ 80 % с речью» заменить на «≥ 80 % с речью или текстом в кадре»; тем — сколько получится естественно (≥ 5). Ролики своего авторства в коллекцию не берутся.

## 13. Распознавание речи: faster-whisper large-v3

**Решение (15.10, MEM-16).** Основная модель ASR — **faster-whisper large-v3** на GPU; **small** — запасной вариант для сервера без GPU; GigaAM не понадобился. Проверка на 10 клипах коллекции (Colab, T4): на 8 клипах с речью смысл понятен полностью у обеих моделей (8/8), large-v3 точнее в терминах и английских словах; скорость large-v3 — RTF 0,13 (минута аудио ≈ 8 с), small — 0,05. Подробно — `research/asr_check/README.md`.

**Проблема для MEM-30:** на речи поверх музыки фильтр тишины (VAD) вырезал голос, транскрипт пустой (клип №66). Нужно ослабить порог VAD и при пустом результате повторять распознавание без VAD. Технически: в Colab faster-whisper требует чтения аудио через ffmpeg (несовместимость с новым PyAV) и библиотек CUDA 12 — учтено в ноутбуке.

## 14. Эмбеддинги: multilingual-e5-large, окно 15 с, без реранкера

**Решение (29.10, MEM-76; дополнение к ADR MEM-18).** Модель эмбеддингов — **intfloat/multilingual-e5-large** (вектор 1024, префиксы «query: » / «passage: »). Речь режется на окна **15 с с шагом 7 с**, подпись — отдельный фрагмент; оценка ролика — лучший фрагмент. **Реранкер не используем.** Сравнение на 91 ролике и 107 контрольных запросах (Colab, T4): e5 — Recall@10 0,963, MRR 0,912, Recall@1 0,869; bge-m3 — 0,963 / 0,860–0,873 / 0,82; поиск по словам BM25 — 0,766 / 0,66. Реранкер bge-reranker-v2-m3 даёт +0,01 MRR, но на CPU ~40 с на запрос. Подробно — `research/embeddings_check/README.md`.

**Для MEM-41:** у e5 сходство «есть ответ» и «нет ответа» почти не различается (0,85 и 0,82) — как показывать «ничего не найдено», решаем там (гибрид с BM25 или порог). bge-m3 остаётся запасным вариантом: та же размерность 1024, замена без изменения схемы БД.

## 7. Остальное без изменений

- Поиск по смыслу речи (4,32) и краткие описания (4,03) — главные функции, приоритеты MVP подтверждены.
- Сервис бесплатный: платная подписка отталкивает 83 %.
- Точность поиска важна: неточный поиск отталкивает 54 %, поэтому требование Recall@10 ≥ 0,8 остаётся.
- Приватность коллекции важна для 46 %. Учётные записи (MEM-53) стоит поднять из бэклога, вход сделать максимально простым.
