# Формат данных ML-конвейера (MEM-79)

Как данные передаются между шагами обработки ролика. Нужен для модели данных (MEM-26) и импорта в БД (MEM-34).

```
ссылка → clip → audio → transcript ─┬→ chunks → embeddings ─→ поиск
                         ocr (1.0) ─┘        └→ enrichment (описание, теги) → topics
```

## Где нужны файлы

- **В рабочей системе файлов нет.** Новый ролик обрабатывает обработчик очереди на сервере и пишет результаты каждого шага сразу в БД; схемы ниже описывают структуру этих данных (таблицы в MEM-26 повторяют их поля).
- **Файлы — только для импорта демонстрационной коллекции.** Распознавание large-v3 на сервере без GPU идёт в разы медленнее, поэтому коллекция обрабатывается в Colab на GPU, результаты скачиваются файлами в этом формате и один раз загружаются в БД (MEM-34). Тот же формат используется в экспериментах (MEM-76, MEM-41).

## Файлы

У каждого ролика есть внутренний номер `clip_id` (целое число). Каждый шаг пишет один файл с этим номером в имени и читает файл предыдущего шага. Кодировка — UTF-8, время — в секундах с двумя знаками после запятой.

| Шаг | Файл | Схема | Кто пишет |
|---|---|---|---|
| Добавление | `clips/{clip_id}.json` | [clip](schemas/clip.schema.json) | backend |
| Аудио | `audio/{clip_id}.wav` — 16 кГц, моно; **удаляется после распознавания** | — | загрузчик (yt-dlp + ffmpeg) |
| Речь | `transcripts/{clip_id}.json` | [transcript](schemas/transcript.schema.json) | faster-whisper large-v3 |
| Текст в кадре (1.0) | `ocr/{clip_id}.json` | [ocr](schemas/ocr.schema.json) | OCR по ключевым кадрам |
| Фрагменты | `chunks/{clip_id}.json` | [chunks](schemas/chunks.schema.json) | разбиение |
| Векторы | `embeddings/{clip_id}.npy` + `embeddings/{clip_id}.json` | [embeddings_meta](schemas/embeddings_meta.schema.json) | модель эмбеддингов |
| Описание и теги | `enrichment/{clip_id}.json` | [enrichment](schemas/enrichment.schema.json) | языковая модель (Kimi) |
| Темы | `topics.json` — один на коллекцию | [topics](schemas/topics.schema.json) | BERTopic |

## Правила

- **Дубли:** пара `(platform, external_id)` уникальна; повторная ссылка на тот же ролик не создаёт новый `clip_id`.
- **Статус** ролика в `clips`: `new → downloading → transcribing → indexing → enriching → done`, при сбое — `error` с текстом в `error`.
- **Речи нет** — `segments: []`; тогда фрагменты строятся только из подписи и (в 1.0) текста в кадре.
- **Фрагменты:** подпись — отдельный фрагмент `source = caption` без таймкодов; речь режется окнами `window` секунд с шагом `stride` (окна перекрываются). Одинаковые соседние окна не повторяются. `chunk_id = {clip_id}_{номер из 3 цифр}`.
- **Векторы:** матрица float32 `[число фрагментов × 1024]`, нормирована по L2 (косинусная близость = скалярное произведение). i-я строка — i-й фрагмент из `chunk_ids`. В БД — колонка `vector(1024)` pgvector, по одной строке на фрагмент.
- **Теги:** `source = auto` — от модели, `user` — добавлены вручную; при пересчёте ручные теги не трогаются.
- **Темы:** пользователь может переименовать тему (`name_source = user`), при пересчёте название сохраняется.
- **Поиск выдаёт ролики целиком:** оценка ролика — лучший из его фрагментов; таймкоды фрагментов нужны, чтобы показать, почему ролик найден.

## Параметры

- Модель эмбеддингов — `intfloat/multilingual-e5-large`, разбиение — окно 15 с, шаг 7 с (MEM-76, decisions.md §14). У e5 к тексту добавляются префиксы: «passage: » для фрагментов, «query: » для запросов.
