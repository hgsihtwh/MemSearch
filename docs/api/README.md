# REST API (MEM-27)

[`openapi.yaml`](openapi.yaml) — целевой контракт OpenAPI 3.1, версия 0.2.0, префикс `/api/v1`.
Обновлён по экспорту «RU · Все экраны.png»: аккаунты и ручные подборки входят в текущий объём.
Пока реализован только `/health`. Схема хранения аккаунтов, подборок и метаданных ролика
реализована миграциями `0001`–`0004`; бизнес-логика нового API ещё требует реализации.

## Аккаунт и доступ

- Почта/пароль: `POST /auth/register`, `/auth/login`, `/auth/refresh`, `/auth/logout`.
  При регистрации создаётся одна личная видеоколлекция. `/me` возвращает профиль и позволяет изменить имя.
- Сессия возвращает Bearer access-токен на 15 минут и refresh-токен на 30 дней. Refresh
  ротируется, выход отзывает текущую пару. Анонимные ключи коллекции больше не используются.
- Сброс пароля: `/auth/password/forgot` → письмо → `/auth/password/reset`. Ссылка одноразовая,
  действует 30 минут, повторная отправка через 45 секунд. После сброса нужен повторный вход.
- Вход через Telegram: `POST /auth/telegram` → подтверждение ботом → опрос
  `GET /auth/telegram/{challenge_id}` с секретом `X-Telegram-Login-Token`. Сессия выдаётся один раз.
  Telegram-аккаунт может не иметь почты; добавить её с подтверждением позволяют `/me/email-code` и `/me/password`.
- Подключение бота к существующему аккаунту: `/telegram/link-code` → `/telegram/link`.
  Бот получает только результат привязки, а ссылки отправляет в `/bot/clips` со своим
  `X-Bot-Token` и Telegram ID из события. Пользовательские токены боту не передаются.
  Привязка бота и Telegram-идентичность для входа хранятся отдельно: отключение бота
  или очистка коллекции не лишает пользователя возможности войти.

Каждый запрос ограничен личной коллекцией текущего аккаунта. Чужие ролики, теги, темы
и подборки возвращают 404. Идентификатор владельца клиентом не задаётся.

## Соответствие экранам и сценариям

| Экран / действие | API |
|---|---|
| Профиль, статистика, подключения | `GET /me`, `GET /collection` |
| Завершить или пропустить онбординг | `PATCH /collection` с `onboarding_done=true` |
| Проверить ссылки перед добавлением | `POST /clips/validate` — формат, платформа и дубли, без создания роликов |
| Добавить ссылки, посмотреть статусы, повторить ошибку (ПР-1, ПР-6) | `POST /clips`, `GET /clips/statuses`, `POST /clips/{id}/retry` |
| Главная и «Недавно обновлённые» | `GET /clips`, сортировка `newest`, `oldest` или `updated` |
| Найти ролик и оценить результат (ПР-2, ПР-3) | `POST /search`, `POST /search/feedback` |
| Карточка, совпадения и виджет оригинала | `GET /clips/{id}?q=…` |
| Все подборки: автоматические и ручные | `GET /groups` — общий список с поиском, фильтрами и сортировкой |
| Автоматические темы (ПР-5) | `GET /topics`, `PATCH /topics/{id}`, ролики через `GET /clips?topic_id=…` |
| Ручные подборки | `GET/POST /playlists`, `GET/PATCH/DELETE /playlists/{id}` |
| Добавить или убрать ролик из ручной подборки | `PUT/DELETE /playlists/{id}/clips/{clip_id}` — ролик остаётся в коллекции |
| Исключить ролик из автоматической темы | `DELETE /topics/{id}/clips/{clip_id}` — исключение сохраняется при пересчёте темы |
| Добавить / убрать тег, предложения при вводе | `POST/DELETE /clips/{id}/tags…`, `GET /tags?q=…` |
| Массовый перенос расширением (ПР-4) | `POST /imports`, `POST /imports/{id}/batches` |
| Удалить ролик / все сохранённые данные | `DELETE /clips/{id}`, `DELETE /collection` с подтверждением |
| Поиск по загруженной картинке (ПР-7, после 1.0) | `POST /search/image` |

Старые номера ПР сохранены для связи с SRS. Новые сценарии аккаунтов и ручных подборок
нужно внести в актуальную SRS; номера требований для них пока не назначены.

## Поиск, фильтры и карточка

Список роликов и поиск поддерживают платформы, даты добавления `[added_from, added_to)`,
статус, тему, ручную подборку и несколько тегов (`tag_mode=any/all`). Фильтры объединяются
через И; платформы внутри списка — через ИЛИ. Пустые фильтры опускаются. Даты — RFC 3339
с часовым поясом, граница `from` раньше `to`. Поиск по подборкам — по названиям; даты там относятся к созданию.

Одна карточка в выдаче — один ролик. `match` содержит лучшую цитату, источник и таймкоды;
`GET /clips/{id}?q=…` возвращает список `matches` для вкладки «Совпадения». Подсветка
задаётся диапазонами `[start, end)` в символах Unicode с нуля. Для оценки нужны `query_id`,
исходный `q`, `clip_id`, сквозная позиция с единицы и `relevant`.

Пагинация поиска использует неизменный пул кандидатов на 15 минут. `total` — число
уникальных роликов этого пула после фильтров, а не всех возможных семантических совпадений.
После истечения курсора сервер возвращает 410, клиент повторяет поиск без курсора.

## Состояния и ограничения

- `searchable` показывает доступность поиска до завершения полной обработки. `stats.processed`
  считает завершённый полный проход, `stats.searchable` — уже доступные для поиска ролики.
- Процент обработки может быть `null`: тогда показывается этап. Уверенность совпадения также
  `null` до калибровки; она не является вероятностью и не выводится напрямую из сходства e5.
- Видео открывается через виджет TikTok/VK. Переход к секунде зависит от платформы; при
  ошибке виджета остаётся ссылка на оригинал. Надпись «удалён автором» — только для причины `removed`.
- Удаление ручной подборки не удаляет ролики. Удаление всех данных очищает коллекцию,
  подборки, импорт и подключение бота; аккаунт сохраняется. Автоматические темы и ручные
  подборки различаются `kind=auto/manual`, а не признаком переименования `name_source`.
- До 10 ссылок при ручном добавлении, до 100 в пачке импорта, до 24 символов в теге.
  Последняя пачка импорта содержит `finished=true` и может быть пустой; обработка идёт отдельно.
- Состояние установки расширения/PWA, загрузка интерфейса и отсутствие сети определяются
  клиентом. `last_import_at` возвращает дату последнего завершённого переноса.
